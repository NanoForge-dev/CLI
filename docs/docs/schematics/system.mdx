## Overview

The `system` schematic writes one ECS system function, with a default export used for code
generation and an `EDITOR_SYSTEM_MANIFEST` that the NanoForge editor reads to show the system.
[`nf create system`](../commands/create) runs it in the systems folder of the app.

## Usage

```bash
schematics @nanoforge-dev/schematics:system --part=client --name=movement
```

## Options

| Option      | Type                   | Default   | Description                                                                          |
| ----------- | ---------------------- | --------- | ------------------------------------------------------------------------------------ |
| `name`      | `string`               | `example` | System name. `movement` gives the function `movementSystem` in `movement.system.ts`. |
| `part`      | `"client" \| "server"` | required  | Picks the package the types are imported from (see the warning below).               |
| `directory` | `string`               | `.`       | Folder to write to.                                                                  |
| `language`  | `"ts" \| "js"`         | `ts`      | `.ts` or `.js` file.                                                                 |

## Generated file

`<directory>/<name>.system.ts`, here for `--name=movement --part=client`:

```ts movement.system.ts
import { type Context } from "@nanoforge-dev/common";
import { type EditorSystemManifest, type Registry } from "@nanoforge-dev/ecs";

import { ExampleComponent } from "../components/example.component";

export const movementSystem = (registry: Registry, ctx: Context) => {
  const entities = registry.getZipper([ExampleComponent]);

  entities.forEach((entity) => {
    if (entity.ExampleComponent.paramA === "end") {
      ctx.app.setIsRunning(false);
      return;
    }

    if (entity.ExampleComponent.paramB === 0) entity.ExampleComponent.paramA = "end";

    if (entity.ExampleComponent.paramB >= 0)
      entity.ExampleComponent.paramB = entity.ExampleComponent.paramB - 1;
  });
};

// * Required to generate code
export default movementSystem.name;

// * Required for the editor to display the system and generate code
export const EDITOR_SYSTEM_MANIFEST: EditorSystemManifest = {
  name: "movement",
  description:
    "This system end the game when paramB reaches 0 for any entity with ExampleComponent",
  dependencies: ["ExampleComponent"],
};
```

The example system works on `ExampleComponent`, imported from `../components/example.component`.
That file exists only if you created a component named `example`. Replace it with your own
components.

## System signature

Every system has this shape:

```ts
(registry: Registry, ctx: Context) => void
```

- `registry` is the ECS registry. `registry.getZipper([...])` returns the entities that have all
  the given components.
- `ctx` is the app context: `ctx.app`, `ctx.network` and the other engine services.

Add the system to the game in `src/main.ts` with `registry.addSystem(movementSystem)`.

## Editor manifest

| Field          | Required | Description                                                                |
| -------------- | -------- | -------------------------------------------------------------------------- |
| `name`         | yes      | Name shown in the editor.                                                  |
| `description`  | yes      | What the system does.                                                      |
| `dependencies` | yes      | Names of the component classes the system reads with `registry.getZipper`. |

## Examples

A client system in the systems folder:

```bash
schematics @nanoforge-dev/schematics:system \
  --part=client --name=physics --directory=src/systems
```

A JavaScript server system:

```bash
schematics @nanoforge-dev/schematics:system \
  --part=server --name=sync-state --language=js --directory=src/systems
```
