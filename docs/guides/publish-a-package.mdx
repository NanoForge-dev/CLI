---
title: Publish a package
description: Share components, systems or assets on the NanoForge registry
---

Once you have written components, systems or assets that others can use, publish them as a package
on the NanoForge registry. Other projects can then get it with `nf install`.

<Steps>
  <Step title="Log in">

    Get an API key from [your registry dashboard](https://registry.nanoforge.eu/dashboard/registry),
    then run:

    ```bash
    nf login
    ```

    `nf login` asks for the key, checks it with the registry, and saves it in `.nanoforgerc` in
    your home folder. Add `--local` to save it only for the current folder.

  </Step>

  <Step title="Write the manifest">

    Put what you share in a folder of its own, with a `nanoforge.manifest.json` at its root:

    ```json nanoforge.manifest.json
    {
      "name": "@my-org/health-bar",
      "version": "1.0.0",
      "type": "package",
      "description": "A health bar above each entity",
      "contents": [
        { "kind": "@nanoforge/ecs:component", "path": "src/health-bar.ts", "export": "HealthBar" }
      ]
    }
    ```

    `name` is `@scope/name`, in a scope your key may publish in (your username's, by default).
    `version` is a semver version, and `type` is `package`. The other fields are listed in
    [the package manifest](/docs/cli/commands/registry#the-package-manifest).

  </Step>

  <Step title="Publish">

    From that folder:

    ```bash
    nf publish
    ```

    `nf publish` zips the folder, prints the files it packed, and publishes it as
    `@my-org/health-bar@1.0.0`. It leaves out secrets (`.env*`, `.npmrc`, `.netrc`,
    `.nanoforgerc`, keys), `.git`, `node_modules`, `nf_modules` and `.nanoforge` folders, and
    `dist` unless the manifest points into it. It doesn't read `.gitignore`: every other file is
    sent. Run `nf publish --dry-run` first to see the list without publishing. Others now install
    it with `nf install @my-org/health-bar`.

    A version is published once: to publish a change, raise `version` first.

  </Step>

  <Step title="Remove a version (if needed)">

    ```bash
    nf unpublish
    ```

    `nf unpublish` removes the version named in the manifest of the current folder. Its number
    can't be published again.

  </Step>
</Steps>

To remove the saved key from your machine, run `nf logout`. The four commands are described in
[registry commands](/docs/cli/commands/registry).
